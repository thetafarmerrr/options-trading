# /session-wrap — 收尾：同步所有状态文件 + 追加对话日志

> 适用时机：每日任务全部完成后，用户准备结束会话或开新对话前。
> 触发词："收尾" "wrap" "session-wrap" "同步状态" "保存进度"

---

## 执行清单

按顺序完成以下 5 项，每完成一项报告状态。

### 1. 更新 `.claude/CLAUDE.md` 的"当前状态"段

更新以下字段：
- `Phase X Day N` → 当天
- 模拟盘笔数、持仓、浮盈
- 训练最新分数（B + 当天轮转模块）
- 工具版本号（如有升级）
- 阅读进度

保持其他段落不变（配合方式、每日规则、对话风格不动）。

### 2. 更新 `MASTER_PLAN.md` 的"七、当前状态"段

和 CLAUDE.md 对齐，字段略有不同（多了训练速度 s/题、少了阅读进度）。新增搁置项按 `| 内容 | 激活时机 | 记于 |` 格式追加到搁置列表。

### 3. 更新 `memory/quant-plan-state.md`

路径：`/Users/mm/.claude/projects/-Users-mm-Documents-AIcode/memory/quant-plan-state.md`

更新字段：Phase/Day、模拟盘、训练分数、工具版本/天数、阅读进度。保持 YAML frontmatter 不变，只改正文数字。

### 4. 追加到 `docs/conversation-log.md`

格式参照已有 8.x 节。内容包括：
- 本节标题（如 `### 8.X Day XX-XX：主题一句话概括`）
- 触发事件
- 讨论的关键决策及理由（不列代码，列"为什么这样选"）
- 拒绝的建议及理由
- 工具改动摘要
- 训练分数
- 新规则/新约定

在文件末尾的最后一个 `| ... |` 行之后追加，保持 markdown 格式。

### 5. 最终核对

用 git status 列出所有未提交的变更文件，提醒用户是否需要 commit。

---

## 原则

- **不编造数据**。训练分数、浮盈金额等只填本次会话中实际出现的数字
- **不一致时先问用户**。如果两个文件（如 CLAUDE.md vs MASTER_PLAN.md）的同一字段有冲突，指出差异让用户决定
- **对话日志只记决策和理由**，不贴代码块，不列函数签名
- **改文件前先读**——确认当前内容再编辑，避免基于记忆覆盖

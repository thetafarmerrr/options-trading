### 2. launchd 自动采集 EPERM 定位 + 修复 ✅（plist 在 ~/Library/LaunchAgents，不入 repo）
- **症状**：iv_collector 从装上起 runs 全 exit 126「Operation not permitted」，从未自动跑成一次。手动 --watch 兜底让数据看起来齐全 → 没人发现（自动化不验证的教训）。
- **根因**：macOS Sequoia TCC——launchd 唤起的 `/bin/bash` 无 ~/Documents 读权；对照 monitor-stop 用 python3（有 FDA）6100 次 exit 0 → 是 bash 缺授权非脚本/路径问题。A/B：同脚本 /tmp exit 0、~/Documents EPERM。
- **修**：/bin/bash 加「完全磁盘访问权限」。reload + kickstart：runs=1 exit 0（周六=周末守卫静默退出，无 scheduler.log 属预期；能 exit 0 反证 FDA 已生效）。
- **plist 三采**：09:30/14:56 → **09:15/09:30/14:50**，对齐手动 --watch 的 WATCH_TIMES，独立短进程逐点触发避开常驻休眠冻结。
- **分工定型**：iv_collector 免手动（launchd 自动），iv_collector_scheduler.log 看自动结果；monitor-stop 不受影响（python3 有 FDA）。前提：Mac 采集时点唤醒。dedup 按 (日期,品种,时点) 同分钟重跑无害覆盖。
- launchd.log 尾部 EPERM 为 reload 前旧 fire 历史（reload 重置计数不清日志），已追加分隔标注防未来误读。
